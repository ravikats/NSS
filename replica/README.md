# Local Oracle Replica of the UAT DB (NETWORK_SETTLEMENT_UAT)

Local copy of the UAT Oracle schema + reference data, used as a safe test target
for the Go services (`tlfsvc`, `outsvc`, `binsvc`, `mpgsvc`, scheduler). Lives in
a Docker `gvenzl/oracle-free` (23ai) container. **Transaction data is NOT loaded**
(see "Excluded tables" below) per the owner's directive.

## Rebuild procedure (from scratch)

1. Start container (above) and wait for "DATABASE IS READY TO USE" in `docker logs`.
2. Extract schema DDL from UAT (rewrites `ddl.sql`):
   `go run ./cmd/extract_ddl` with `ORACLE_DSN=<uat dsn>`
3. Create user + apply DDL (idempotent; identity columns are emitted as
   `GENERATED BY DEFAULT` so PKs can be restored):
   `ORACLE_DSN_SYSTEM=<system dsn> ORACLE_DSN=<local dsn> LOCAL_USER=NETWORK_SETTLEMENT_UAT LOCAL_PASS='J6erQ$o6E24' DDL_FILE=ddl.sql go run ./cmd/apply`
4. Truncate local copy-set tables (idempotent): `ORACLE_DSN=<local dsn> go run ./cmd/truncate`
5. Copy reference data: `ORACLE_DSN_UAT=<uat dsn> ORACLE_DSN=<local dsn> go run ./cmd/copy`
6. Verify: `ORACLE_DSN_UAT=<uat dsn> ORACLE_DSN=<local dsn> go run ./cmd/verify`
7. (Optional, Mercury staging) apply the idempotent local-only setup:
   `sqlplus NETWORK_SETTLEMENT_UAT@localhost:1521/FREEPDB1 @mercury_staging_setup.sql`

## Tools

- `cmd/extract_ddl` — `DBMS_METADATA.GET_DDL` for sequences/tables/indexes/views/
  function/types, with STORAGE/TABLESPACE/SEGMENT_ATTRIBUTES stripped and identity
  columns rewritten to `GENERATED BY DEFAULT AS IDENTITY`.
- `cmd/apply` — creates the schema user (+ grants) and applies `ddl.sql`.
  Multi-pass + idempotent (skips existing objects, retries failed FK deps).
- `cmd/truncate` — truncates every table in the copy set (empty the data).
- `cmd/copy` — streams each copy-set table from UAT to local in 200-row batches.
  Uses `SELECT *`/bind insert; NUMBERs arrive as strings so 19-digit PAN ranges are
  preserved exactly.
- `cmd/verify` — per-table row-count comparison; fails only on unexpected diffs.

## Gotchas learned

- The `IRF` drive is **exFAT** — Docker bind mounts there cannot honor Unix
  ownership, so the Oracle container fails to create data files. Use a **Docker
  named volume** (`-v oracle-local-data:/opt/oracle/oradata`) instead.
- go-ora cannot bind PL/SQL `BOOLEAN`; `DBMS_METADATA.SET_TRANSFORM_PARAM` must be
  called with literal `TRUE`/`FALSE` inlined in the statement text.
- `DBMS_METADATA.GET_DDL` returns a trailing `;` and the schema-qualified name;
  the apply tool splits on bare `/` lines and strips leading `--` comment blocks.
- Running two copy instances concurrently causes ORA-00001 PK collisions — always
  truncate before a single copy run.
